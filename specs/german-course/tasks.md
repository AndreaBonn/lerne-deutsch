# german-course - Task

Una riga per task: `id | fase | testo | stima | verify | livello | dip | par | rollback | R`.
Ogni test si scrive prima del codice e si vede rosso; su codice esistente si rompe a mano il
codice per vedere il rosso e si ripristina. Ogni `verify` è rosso sul commit di partenza del
task.

Gate di chiusura di ogni fase, non ripetuti nelle righe (R31): `npm run lint`, `npm test`,
`npm run test:mutations`, `npm run test:dom`, `node scripts/validate.mjs <lang>` per it, en,
es, fr, pl, `node scripts/parity.mjs`, `node scripts/check_precache.mjs`,
`node scripts/check_swversion.mjs`, `node scripts/coverage.mjs --min 99`. Da F1 in avanti
anche `npm run check:porting -- --level <L>` sui livelli chiusi.

Fra due task della stessa fase `validate.mjs` e la suite DOM possono essere rossi (plan.md
A13). `npm test` deve essere verde alla fine di ogni turno.

Ciclo dei lotti di contenuto (righe `a`-`e` di ogni unità):
- `a` core de + nakładka it secondo `curriculum.md`: lezioni, vocab con `plural`, dialogo, esercizi, `theory` con `{contrast}`/`{trap}` per italofoni, tag `GRAMMAR_REF`.
- `b` gate D8: `npm run review:lot -- <unit> --lang it`, correzione dei finding, nuovo giro fino a `pass` (massimo 4 giri più 1 di conferma, poi parcheggio per l'utente; Q4 A). B2-C2: anche campione umano.
- `c` nakładki en+es, `{contrast}`/`{trap}` scritti da zero per ciascuna lingua, `review:lot` per lingua.
- `d` nakładki fr+pl, come `c`.
- `e` audio: `audio:strings`, `audio:build`, `audio:prune` (dry-run, poi `--apply`), `recordings.test.mjs`.

Parallelismo dei lotti: `a` di unità nello stesso file è `seq` (fusione per indice nello
stesso array); unità in file diversi possono andare in parallelo dopo T1.01 (il curriculum
fissa cosa ogni unità presuppone). `c` e `d` sono `ok` fra loro. `e` è `seq` perché
`scripts/audio-strings.json` e `data/audio-index.js` sono condivisi.
